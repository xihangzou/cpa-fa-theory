# Delivery and manual execution

Repository: `xihangzou/cpa-fa-theory`. Existing visibility: public. Delivery branch: `main`.

Setup is authorized to publish this scaffold, contracts and issues. It is not authorization to execute production issues, launch workers, switch models, integrate books or generate cards. All model assignments are recommendations for the user's next manual launch, not GitHub assignees or a dispatch instruction.

For an individually launched issue, inspect status and fetch main. Record the actual current base and actual dependency output revisions. `base_sha` in the plan records the original setup baseline, not an instruction to execute from that empty root. Use the latest compatible delivery revision after prerequisites are verified. A closed issue alone is not proof that usable output exists. Report contract/source drift for Astra planning revision.

Use an isolated checkout when other manual work is active. Preserve unrelated changes. No existing branch/PR policy was found at setup; the standard manual launch may save only its scoped approved files to main after fetching and resolving changes conservatively. Never force-push. If a PR policy or integration approval later applies, keep the issue open until outputs are present on main. Source/contract changes need explicit planning reconciliation, not silent scope growth.

Commit only intended Markdown/JSON, code/tests and evidence. Raw PDFs/JPGs, source caches, cropped figures, APKGs, credentials and intermediate OCR extracts are excluded. The destination for future learner Markdown is the scoped `project/BOOK/chunks/` and `project/BOOK/merged/` paths; this is not permission to upload bulk source media. If essential figure media must be published, report the exact artifact and required destination decision first.

Remote verification means re-fetch the actual changed paths at the saved commit and compare bytes/hashes. Post evidence or close the selected issue only when the user's launch authorizes those actions and every acceptance criterion passes with outputs accessible on main. Stop after that issue; do not launch descendants.

On two failed Luna attempts at the same criterion, preserve evidence and recommend a Sol rerun to the user. No automatic retry loop, model switch or worker dispatch. If source interpretation is required, report the ambiguity instead of guessing.
